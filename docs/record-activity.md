# Активность и задачи по записи

## Обновление удалённого сервера

1. Сделайте резервную копию базы.
2. Выполните `scripts/migrate-record-activity.sql` в базе ERP до запуска нового API.
   Скрипт добавляет таблицы и индексы; существующие записи и роли не изменяет.
   Повторный запуск допустим.
3. Обновите зависимости, соберите API и интерфейс, перезапустите API обычным способом.
   Если миграция активности уже была выполнена ранее, выполните дополнительно
   `scripts/migrate-my-tasks-system-page.sql`: она регистрирует «Мои задачи»
   в разделе «Страницы → Системные». Название, иконка и порядок настраиваются
   там; повторная миграция не перезаписывает эти настройки.
4. В разделе «Администрирование → Сущности → нужная сущность → Поля»
   включите «Звонки, договорённости и задачи».
5. В конструкторе карточек добавьте блок «Активность» и сохраните карточку.
   В стандартной форме история доступна без создания отдельного шаблона.

## Что хранится

Звонки, письма, встречи и заметки регистрируются вручную. Завершённая задача
типа звонок/письмо/встреча также создаёт взаимодействие с указанным результатом.
Это не интеграция с телефонией и не отправка электронной почты.

Активность принадлежит записи, а не зеркальной странице. При исправлении и
удалении взаимодействия сохраняется отдельное событие с прежним текстом и причиной.
Перенос задачи сохраняет старый и новый срок. Полное удаление родительской записи
удаляет её активности, задачи и уведомления по внешним ключам.

Права чтения повторяют доступ к записи, включая собственные записи, ограничения
статусов и зеркальные страницы. Изменение истории требует права изменения записи;
обычный пользователь исправляет только собственные взаимодействия. Ответственный
может завершить, перенести или отменить свою задачу, пока у него есть доступ к записи.
Гостевой доступ не разрешает изменения. Технические аккаунты не назначаются.

## Автоматизации

Новые события: добавление взаимодействия, завершение задачи.
Новые проверки: отсутствие активности, время в статусе, срок задачи.
Новые действия: внутреннее уведомление ERP и создание задачи.

Для проверки по времени выбирается минута, час, день или месяц. У ежедневной
проверки задаётся час и часовой пояс, у ежемесячной также день 1–28.
В существующей проверке даты также можно задать расписание.
Дни отсутствия активности/нахождения в статусе — календарные интервалы по 24 часа,
а не рабочие дни. Отрицательное смещение задачи означает «до срока», положительное — «после».

Частота проверки не равна частоте сообщений. Без интервала повторения правило
выполняется один раз для данного периода бездействия/нахождения в статусе/срока задачи.
При повторении задаётся интервал в часах и необязательный лимит общего числа выполнений.
Выход/возвращение в статус либо новый выбранный контакт начинает новый период.
Изменение настройки правила также начинает новый период.

В уведомлении используются заданный текст и разрешённая получателю ссылка на запись.
Получатели выбираются явно, из пользовательских полей записи или как ответственный
за задачу. Неподходящие/заблокированные/технические пользователи и пользователи без
доступа пропускаются. В журнале выполнения действий отражается число получателей.
Повторное действие создания задачи не создаёт вторую открытую задачу того же
правила/действия/получателя по этой записи.

## Надёжность и ограничения

Минута — частота работы планировщика, а не частота полного обхода ERP.
Каждое правило проверяет только свою сущность в своё расписание.
Задачи с точным напоминанием выбираются по индексу времени напоминания.
История запусков и защиты от дублей хранится в базе.

После остановки сервера не отправляется очередь всех пропущенных повторов:
при ближайшей проверке выполняется максимум один актуальный запуск.
Если процесс аварийно завершился между резервированием запуска и действием,
в журнале автоматизаций остаётся ошибка прерванного выполнения. Такие действия
не повторяются автоматически: повтор произвольного вебхука или изменения записи
может быть опасен. Проверьте результат перед ручным повторением.

Статусные переходы показываются как событие изменения статуса без копирования
скрытых исторических значений. Автоматический захват звонков/писем и учёт рабочих
дней в новых проверках в эту версию не входят.
