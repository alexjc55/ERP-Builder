# Журнал безопасности: установка и ограничения

**До запуска обновлённого API** примените к базе данных миграции по порядку:
1. `lib/db/drizzle/0026_bouncy_forge.sql` — если журнал ещё не установлен.
2. `lib/db/drizzle/0027_noisy_magma.sql` — управление хранением журнала.
Это **новая миграция**, дополнительная к миграции 0025 для отзыва сессий.
Используйте принятый порядок обновления базы на удалённом сервере, предварительно
проверив историю применённых миграций. Не запускайте повторно все старые миграции
Drizzle без проверки: предыдущие изменения структуры базы на сервере с FastPanel
применялись вручную.

Обновите серверную часть (API) и интерфейс совместно. Загрузите новые переводы,
выполнив следующую команду **в SSH-терминале из корня проекта, не в SQL-редакторе**:

```sh
corepack pnpm --dir scripts run seed-translations --prefix=securityAudit.
corepack pnpm --dir scripts run seed-translations --prefix=securityRetention.
```

Менять секрет шифрования или существующие ключи агентов и интеграций не требуется.
Действующие пользовательские токены JWT остаются действительными, пока актуальна
их версия сессии. Новые JWT получают случайный идентификатор: два входа в одну
секунду больше не будут иметь одинаковый идентификатор для сопоставления в журнале.

## Что записывается

В списке и подробностях рядом с ID показываются текущие имена пользователей,
названия ролей, агентов, интеграций, сущностей и подписи записей, если их ID
сохранены в событии. Это справочные подписи при чтении, не исторический снимок:
после переименования будет новое имя, после удаления — ID с пояснением.
Для записи используется первое непустое активное текстовое/числовое поле
(приоритет у ключевого поля, затем порядок полей). Файлы и вычисления не раскрываются.
Старые события без сохранённого ID объекта дополнить задним числом нельзя.
Имена доступны только тем же человеческим супер-администраторам, что и сам журнал.

- Успешные и неудачные попытки авторизации через HTTP.
- Ответы 401/403 и ответы 404 от API.
- Критичные изменения пользователей, ролей, агентов, интеграций и настроек Google.
- Действия с гостевыми ссылками, вход от имени другого пользователя и отзыв сессий.

Журнал и настройки хранения доступны в разделе **«События → Безопасность»** только супер-администраторам,
вошедшим в собственную учётную запись: не гостям, не агентам и не в режиме входа
от имени другого пользователя. Отметка «Просмотрено» не удаляет и не переписывает
исходное событие. Удаляются только просроченные события по правилам хранения,
а не произвольно выбранные свежие записи.

Полные тела запросов, пароли, секреты, токены Bearer, коды OAuth, параметры URL
и произвольные пути, не соответствующие маршрутам API, **не сохраняются**.
Ссылки на сессии — это хеши с секретным ключом, а не данные, позволяющие войти
в систему. В подробностях указаны **запрошенные изменения**, а не полный
транзакционный снимок базы «до и после». Для браузера сохраняется только
обобщённое название семейства браузеров.

Перед выполнением критичного запроса система должна сохранить запись о попытке.
Результат записывается отдельно. Повторные попытки могут объединяться.
**Попытка без результата не доказывает ни успех,
ни откат:** операция могла завершиться ошибкой или успеть сохраниться перед
аварийной остановкой процесса. Если сохранить результат не удалось, в серверный
лог записываются структурированные сведения без секретов. Это не атомарный журнал
изменений базы и не защита от подмены данных владельцем базы или сервера.

Для входящей интеграции HTTP 202 означает приём запроса в очередь,
**а не успешное создание рабочих данных**. Результат обработки нужно смотреть
в истории входящих доставок по сохранённому `deliveryId`.
Учётная запись связывается с запросом только после проверки данных авторизации.

Предупреждения формируются при успешных критичных изменениях настроек и учётных
записей, отказах в доступе, повторных неудачных входах — не менее пяти за десять
минут для одного введённого логина — и успешном входе после таких отказов.
**Автоматическая блокировка не реализована.** Предупреждения в интерфейсе
обновляются каждые 30 секунд и видны только при открытом приложении.
Внешние уведомления не настроены.

## Определение IP — настройка на удалённом сервере

Пошаговая проверка для nginx/FastPanel: [security-proxy-check.md](security-proxy-check.md).

По умолчанию система доверяет только адресу непосредственного сетевого соединения.
Если API работает за nginx, это может быть адрес nginx, а не посетителя.
Обновление не включает доверие к пересланным заголовкам автоматически.

После проверки подключения nginx к API, правил межсетевого экрана и настроек
передачи заголовков задайте переменную `SECURITY_TRUSTED_PROXY_CIDRS`:
точные IP-адреса или подсети доверенных прокси в формате CIDR, через запятую.
Например, локальные адреса loopback подходят **только если** nginx действительно
подключается через них и схема подключения проверена.
**Никогда не указывайте `0.0.0.0/0` или `::/0`.**
После изменения переменной перезапустите API.

Определение адреса начинается с непосредственного соединения. Затем система
проходит заголовок `X-Forwarded-For` справа налево, только через доверенные прокси.
Недоверенные или некорректные цепочки адресов игнорируются.
Адрес соединения, выбранный адрес клиента и способ его определения сохраняются
отдельно.

**IP не устанавливает личность человека.** Проверьте, что порты API и PostgreSQL
не доступны напрямую из интернета. Это обновление не настраивает межсетевой экран
удалённого сервера.

## Что не охватывается этим функционалом

Из этих таблиц нельзя восстановить события, произошедшие до установки журнала.
Прямые SQL-запросы, действия через SSH, PM2 и изменения серверных файлов обходят
HTTP-аудит. Это относится и к ручной команде восстановления пароля.
При необходимости отдельно настройте защищённый аудит операционной системы
и PostgreSQL, а также отправку очищенных от секретов событий за пределы сервера.
Не записывайте в логи параметры SQL с чувствительными данными, пароли, токены
или исходные тела OAuth-запросов и вебхуков.

## Управление хранением — простые действия

### Экспорт для анализа

В «События → Аудит безопасности» заполните фильтры и нажмите **«Экспорт JSON»**.
Кнопка применяет заполненные фильтры и скачивает все соответствующие строки,
а не только открытую страницу. Пустые фильтры означают весь сохранившийся журнал.
Файл включает время выгрузки, фильтры, количество строк, подробности, текущие
имена объектов, отметки проверки и счётчики объединённых повторов. Время — UTC.
Экспорт не отмечает события просмотренными и не меняет их.

За раз можно выгрузить до 10 000 строк / 20 МБ. При превышении лимита файл
не создаётся: сузьте период и выгрузите несколько файлов. Сервер не сохраняет
копии экспортов на диске. Доступ — только у человеческого супер-администратора
в собственной сессии, как к самому журналу.

Файл содержит персональные данные и сведения безопасности. Передавайте его
только доверенному получателю. Это не резервная копия базы, не архив всех HTTP
запросов и не восстановление уже удалённых событий.

### Сроки и очистка

1. Откройте **«События → Безопасность → Управление хранением»**.
2. По умолчанию обычные события хранятся **30 дней**, важные — **180 дней**.
   К важным относятся тревоги, успешные входы и события критичных операций.
   Отметка «Просмотрено» не сокращает срок хранения.
3. Порог предупреждения о размере по умолчанию — **256 МБ**.
   Это **не жёсткий лимит**: при его превышении свежие важные события не удаляются.
4. Перед сохранением подтвердите, что события старше выбранных сроков будут удалены
   без возможности восстановления из журнала. Важные материалы расследования
   заранее сохраните в отдельной резервной копии.
5. Автоочистка включена по умолчанию и каждую минуту удаляет максимум **1000**
   просроченных записей вместе с их отметками просмотра, одной транзакцией.
   Её можно приостановить. Кнопка ручной очистки с подтверждением обрабатывает
   только одну такую порцию, в том числе при приостановленной автоочистке.
6. Размер, количество строк и повторов, число просроченных событий, результат
   последней очистки и ошибки видны в этом же разделе.

Срок считается от последнего повторения события. При уменьшении срока старые
события могут попасть под ближайшую очистку. Изменения правил тоже записываются
в журнал. Параллельное сохранение чужих настроек не затирается: потребуется
загрузить актуальные значения.

Попытки и отказы без подтверждённой личности объединяются в окнах по пять минут:
сохраняются количество, первая и последняя даты и образец первого запроса.
Успешные входы, успешные изменения и отказы подтверждённых пользователей не объединяются.
В одном окне допускается не более 100 отдельных групп попыток и отказов.
Новые группы сверх этого порога попадают в общую строку с предупреждением:
**индивидуальные источники этих дополнительных попыток не сохраняются**.
Это ограничивает рост от постоянно меняющихся анонимных запросов; не является
ограничителем частоты запросов или общим жёстким лимитом размера всей базы.

PostgreSQL повторно использует освобождённое место: после очистки размер файла
на диске не обязан сразу уменьшиться. Принудительное сжатие с блокировкой
таблиц автоматически не запускается.

Логи PM2 и nginx — отдельные файлы на сервере. Эта очистка на них не действует;
для них отдельно настраивается ротация. Никакие настройки удалённого сервера
этим обновлением автоматически не меняются.

Ограничение частоты запросов, двухфакторный вход администраторов, повторное
подтверждение привилегированных действий, внешние уведомления и усиление защиты
удалённого сервера остаются отдельными мерами безопасности.

### Обращения после завершения сеанса

Отказы `401` с причиной `session_revoked_or_account_inactive` объединяются
в пятиминутные группы только для проверенной, но отозванной сессии. Разные
пользователи, сессии и источники запросов не смешиваются (кроме явно
обозначенного общего переполнения групп). Успешные действия и обычные
отказы в правах остаются отдельными событиями.

В группе сохраняются общий счётчик, первое/последнее время и счётчики
маршрутов в `requestSummary`. Основной запрос, его ID и связанные объекты
представляют **первое обращение**, а не всю группу. Для группы сохраняются
до 32 сочетаний метода/маршрута; обращения сверх этого числа учитываются в
`omittedRequestCount` с явным предупреждением об утрате деталей.
Новые обращения после просмотра снова делают группу непросмотренной.

Рабочие страницы ждут проверки текущей сессии; отклонённая сессия удаляется
из браузера. Старые вкладки со старой версией приложения могут продолжать
обращения до обновления страницы — сервер всё равно отклоняет их.

Это обновление не требует SQL-миграции и не переписывает старые события.
Нужны обновление API и интерфейса; переводы добавлены в обычный seed переводов.
